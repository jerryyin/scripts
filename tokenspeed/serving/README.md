# tokenspeed/serving/ — measuring a running TokenSpeed server

Tools that drive a `ts serve` server over HTTP and read its log (`ts_control::batch_log` lines).
Server flags, server start/stop, fixed-batch decode, serving load, prefill and the real-token prompt
bank are owned by [lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking): the
recipes in `apps/inference_engine_benchmark/recipes/`, `skills/inference_engine/benchmark/scripts/manage_server.py`,
`apps/inference_engine_benchmark/scripts/run_nightly_tiered.py` (retained-KV harness),
`skills/inference_engine/benchmark/scripts/run_evalscope_matrix.py` (with `--output-tokens 1
--prefill-summary` for prefill) and `skills/inference_engine/retained-kv/scripts/prepare_token_corpus.py`
(`--format git-docs` builds the natural-prose text from a Git tree's documentation).

| Path | Measures |
| --- | --- |
| `batch_log.py` | The one parser of the server log (`Prefill`/`Mix`/`Decode batch.` lines and `Finish!` lines: `Finish! RequestStats(...)`, or, in builds that log only the request's mean accepted tokens per verify step (TokenSpeed `1be88db0a7b020d1cc45241eb02935c03d692335`), `Finish! Accept_num_tokens_avg: X`, read as a Finish event with stats `{"acc_len": X}` and no prompt/output token counts) and a log follower; every tool below imports it. `batch_log.py dp-spread LOG --window NAME=START[,END] ...` sums `#new-seq` of the Prefill lines per attention-DP rank in each time window (how evenly data-parallel placement spread a run's prefill work). `#new-seq` is the round's extend rows (TokenSpeed `ts-control/src/batch_log.rs`), so these are prefill rows, not requests: a prompt chunked over k rounds counts k times, a request prefilled only in Mix rounds (beside decode rows) not at all, and the lines carry no request id to count requests exactly; `--tokens` adds per window and rank (and `all`), over the Prefill and Mix lines, the prompt tokens prefilled (`#new-token`, which on a Mix line also holds its decode rows' tokens) and served from the prefix cache (`#cached-token`, counted on a request's first chunk), `cached_share` = cached / (cached + prefilled) (a lower bound of the prompt tokens' cache share), `mix_new_seq` and the Prefill, Mix and cache-hit line counts (whether later turns of a session reach the rank holding their prefix), and `--requests NAME=N` (the window's request count from the client, e.g. AIPerf's profiled requests) prefilled and cached tokens per request; `batch_log.py prefill LOG --benchmark-json BJ [--chunk-cost] [--tail]` reads prefill points (one wave, one output token, e.g. amd-tracking's matrix with `--output-tokens 1 --prefill-summary`) from the log: per-rank chunks, chunk times and request split, validity (prefill tokens = B x L and no prefix-cache hit: RequestStats `cache_tokens == 0` when the log has RequestStats, else every Prefill/Mix line's `#cached-token == 0`; the source used is printed) and batching (steps, most requests present at once, per-step `new_seq/new_token`) |
| `sustained/` | A multi-turn agentic load replayed with EvalScope for a fixed duration, and the decode batch sizes the server actually ran (`build_workload.py`, `run_sustained.sh`, `analyze_sustained.py`, whose `--steady A:B` also gives client metrics over a steady window and `--instances` conversation counts); `prefix_reuse.py` measures how often later turns reuse their previous turn's cached prefix under data-parallel placement; both read the EvalScope database through `evalscope_db.py`, which also defines the steady window (each output names its anchor); `DATASET.md` characterises `lightseekorg/agentic-dataset` |
| `e2e_decompose.py` | Split one serving run's server log into per-rank prefill, decode and idle time, with residency and the round time at full batch; `--benchmark-json` slices a whole log per phase of an amd-tracking EvalScope matrix run (a phase repeated across concurrencies as `PHASE/cB`, slice `PHASE_cB.log`); `--markdown` prints one row per run; `--predict` models a closed-loop benchmark (R requests of L/O tokens at concurrency C) from prefill and decode measurements (`--prefill NAME=` an amd-tracking matrix `--prefill-summary` `benchmark.json`, `--tpot NAME=CFG:` a number or `CSV@POINT` of a `report_retained_kv.py --repetitions-only` table) and swaps measured terms between configurations; `--window-from-aiperf PROFILE_EXPORT` (one per `--log`) decomposes only an AIPerf `profile_export.jsonl` profiling phase (first request start to last request end, over the records InferenceX's agentic aggregate counts: no `benchmark_phase` is profiling, errored records dropped) instead of the start/end rules, which assume fixed-length requests (agentic runs such as InferenceX AgentX), and reports the window's Finish lines (`window_finish_lines`: count, mean nonzero `acc_len`, requests with `acc_len` 0); on a single-rank log (Finish lines carry no DP rank) a gap holding Finish lines for every request running at its start ends decode at the last of them and counts the rest as idle between waves (`finish_split_gaps` per rank: how many gaps, how many start at a Prefill/Mix line such as a turn shorter than one Decode-line interval, and the prefill, decode and idle seconds they were given); `--step-table` (with `--decode-log-interval N`, rounds per Decode line) gives the decode round time from consecutive Decode lines of each rank (gap / N), binned by running batch and context (`avg_seq_len` bucket) over clean gaps only (no Prefill/Mix line of any rank between or just before them, same batch at both ends), with accepted tokens per round and ms per token per request, and per rank all clean gaps pooled (`clean_all`: n, median, p10, p90, min, max; the table's `all` row when there is more than one bin); it lists clean gaps above 1.5x their bin's median (pauses with no logged prefill), counts prefill-held gaps and their excess over the clean step, and Prefill/Mix rounds run while decode requests were resident. It generalizes the full-batch round time above to every batch size, for variable-batch (agentic) runs |
| `correctness/` | Greedy-output consistency: `greedy_prompts.py` builds a seeded prompt set from a text corpus, `greedy_client.py` records outputs for it, `compare_outputs.py` compares runs token by token (`--pair` for several, `--cache-free` for prompts without prefix-cache hits), `probe.py` asks the server for its own top-1 token where two outputs first diverge (`--mode decode-path`, `--mode teacher-forced`, `--summarize`); `eval_agreement.py` asks whether configurations agree on an EvalScope accuracy benchmark (per-repetition scores from a `manage_server.py` run, then a binomial agreement verdict per pair; `compare --counts-from-summary` from the summaries' counts alone, `--admissible-only` without repetitions whose window was not admissible) |

Comparing configurations (ratios with a range-overlap verdict) is `../../numerics/range_compare.py`
over the summary tables these tools write; output degeneracy of any of their outputs is amd-tracking's
`skills/inference_engine/benchmark/scripts/evalscope_degeneracy.py --input LABEL=PATH`.
Tests (CPU, synthetic logs from `log_fixtures.py`): `test_batch_log.py`, `test_e2e_decompose.py`, `sustained/test_sustained.py`,
`correctness/test_correctness.py`, `correctness/test_eval_agreement.py`.

Requirements: the model directory in `MODEL` (or `--tokenizer`), a client Python with `aiohttp`,
`numpy` and `transformers` (an EvalScope virtual environment has them), for
`sustained/` the `evalscope` executable in `EVALSCOPE`, and a checkout of
[lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking) in `AT`: servers are
started, guarded and stopped with its `manage_server.py`, which waits for the GPU set to be idle.

Prefill points from the server log of an amd-tracking matrix run (one wave per point):

```bash
python3 batch_log.py prefill server.stderr.log --benchmark-json RUN/tokenspeed/benchmark.json \
  --chunk-cost --tail --out-json prefill-log.json
```
