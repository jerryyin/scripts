# tokenspeed/serving/ — measuring a running TokenSpeed server

Tools that drive a `ts serve` server over HTTP and read its log (`ts_control::batch_log` lines).
Server flags, server start/stop, fixed-batch decode, serving load, prefill and the real-token prompt
bank are owned by [lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking): the
recipes in `apps/inference_engine_benchmark/recipes/`, `skills/inference_engine/benchmark/scripts/manage_server.py`,
`apps/inference_engine_benchmark/scripts/run_nightly_tiered.py` (retained-KV harness),
`skills/inference_engine/benchmark/scripts/run_evalscope_matrix.py` (with `--output-tokens 1
--prefill-summary` for prefill) and `skills/inference_engine/retained-kv/scripts/prepare_token_corpus.py`
(`--format git-docs` builds the natural-prose text from a Git tree's documentation).

| Path | Measures |
| --- | --- |
| `batch_log.py` | The one parser of the server log (`Prefill`/`Mix`/`Decode batch.` lines and `Finish! RequestStats(...)`) and a log follower; every tool below imports it. `batch_log.py dp-spread LOG --window NAME=START[,END] ...` counts new sequences per attention-DP rank in each time window (how evenly data-parallel placement spread a run's requests); `batch_log.py prefill LOG --benchmark-json BJ [--chunk-cost] [--tail]` reads prefill points (one wave, one output token, e.g. amd-tracking's matrix with `--output-tokens 1 --prefill-summary`) from the log: per-rank chunks, chunk times and request split, validity (prefill tokens = B x L and no prefix-cache hit: RequestStats `cache_tokens == 0` when the log has RequestStats, else every Prefill/Mix line's `#cached-token == 0`; the source used is printed) and batching (steps, most requests present at once, per-step `new_seq/new_token`) |
| `sustained/` | A multi-turn agentic load replayed with EvalScope for a fixed duration, and the decode batch sizes the server actually ran (`build_workload.py`, `run_sustained.sh`, `analyze_sustained.py`, whose `--steady A:B` also gives client metrics over a steady window and `--instances` conversation counts); `prefix_reuse.py` measures how often later turns reuse their previous turn's cached prefix under data-parallel placement; both read the EvalScope database through `evalscope_db.py`, which also defines the steady window (each output names its anchor); `DATASET.md` characterises `lightseekorg/agentic-dataset` |
| `e2e_decompose.py` | Split one serving run's server log into per-rank prefill, decode and idle time, with residency, the round time at full batch and per rank `prefill_to_decode_gap_s` (count, median and largest gap between a Prefill/Mix line and the next Decode line, with both line timestamps, and the stalls above max(2 x (chunk + Decode-line interval), 1 s): a request stalled between its last chunk and its first decode); `--samples SAMPLES_JSONL` (amd-tracking `gpu_admission.py` admission samples, repeatable) adds to each stall its `gpu_activity` before, during and after it: per GPU device busy and the server's own KFD `cu_occupancy`, `queues` and SDMA-time delta, each GPU busy, idle or unobserved and the window all-busy, all-idle or mixed (one GPU idle while its peers spin at a constant `cu_occupancy` = that rank held up on the host while the others wait in a device-side exchange); `--activity-window LABEL=START_UTC,END_UTC` (with `--samples` and `--out-json`) gives the same activity, state and timeline for a stated window (a stall with no Decode line, e.g. after a 1-output request's last Prefill line) and every GPU's observed or unobserved state over all samples, and with `--cache-listing LISTING` (a `find DIR -type f -printf '%T@ %s %p\n'` listing of a Triton cache) the cache files written in each window grouped per kernel with their compile span; `--benchmark-json` slices a whole log per phase (per phase and concurrency for a matrix ladder) of an amd-tracking EvalScope matrix run; `--markdown` prints one row per run; `--predict` models a closed-loop benchmark (R requests of L/O tokens at concurrency C) from prefill and decode measurements (`--prefill NAME=` an amd-tracking matrix `--prefill-summary` `benchmark.json`, `--tpot NAME=CFG:` a number or `CSV@POINT` of a `report_retained_kv.py --repetitions-only` table) and swaps measured terms between configurations; `--chunk-model` fits a chunk-time line t(x) = a + b x (`--chunk-fit NAME=JSON[,JSON]`: through the per-size medians of the busiest rank's chunk time over this tool's measured runs, with the fixed share a/t(x) at the largest fitted size and its spread over repetitions: per size one median per repetition index, the line through every combination of one value per size gives a, b and the fixed share as [min, max]; or `--chunk-line NAME=A_MS:B_US`, a stated line) and what-ifs chunk size and placement (`--chunk-scenario NAME=LINE:CHUNK:GROUPS[:DECODE]`: per `--concurrency-list` C the wave's prefill end, mean own-prompt prefill end and, with DECODE, the wave's decode time and tok/s); `--gap-split A=BENCHMARK_JSON --gap-split B=BENCHMARK_JSON` splits A's mean end-to-end latency gap over B per concurrency of two amd-tracking matrix `benchmark.json` files into a TTFT part (TTFT_A - TTFT_B) and a decode part ((O-1) x (TPOT_A - TPOT_B), O from the file's "Avg Output Tokens"), medians over measured phases, with the measured latency gap, residual, [min, max] over repetition pairs and the larger part (Markdown, `--out-json`); `--point-table JSON...` with `--decode-log-interval N` tabulates this tool's JSON per run: the busiest rank's prefill chunks x median chunk ms, the full-batch decode round (per rank median full-batch Decode-line gap / N; over ranks the upper median, element n // 2 of the sorted values) and the largest `prefill_to_decode_gap_s` max over ranks; `--line-gaps THRESHOLD_S --log SLICE...` lists per log and rank every gap above THRESHOLD_S s between consecutive batch-log lines with both lines' kinds and log timestamps (timestamps for the prefill-chunk stalls the decomposition only counts, e.g. as `--activity-window` bounds) |
| `correctness/` | Greedy-output consistency: `greedy_prompts.py` builds a seeded prompt set from a text corpus, `greedy_client.py` records outputs for it, `compare_outputs.py` compares runs token by token (`--pair` for several, `--cache-free` for prompts without prefix-cache hits), `probe.py` asks the server for its own top-1 token where two outputs first diverge (`--mode decode-path`, `--mode teacher-forced`, `--summarize`); `eval_agreement.py` asks whether configurations agree on an EvalScope accuracy benchmark (per-repetition scores from a `manage_server.py` run, then a binomial agreement verdict per pair) |

Comparing configurations (ratios with a range-overlap verdict) is `../../numerics/range_compare.py`
over the summary tables these tools write; output degeneracy of any of their outputs is amd-tracking's
`skills/inference_engine/benchmark/scripts/evalscope_degeneracy.py --input LABEL=PATH`.
Tests (CPU, synthetic logs from `log_fixtures.py`): `test_batch_log.py`, `test_e2e_decompose.py`, `sustained/test_sustained.py`,
`correctness/test_correctness.py`, `correctness/test_eval_agreement.py`.

Requirements: the model directory in `MODEL` (or `--tokenizer`), a client Python with `aiohttp`,
`numpy` and `transformers` (an EvalScope virtual environment has them), for
`sustained/` the `evalscope` executable in `EVALSCOPE`, and a checkout of
[lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking) in `AT`: servers are
started, guarded and stopped with its `manage_server.py`, which waits for the GPU set to be idle.

Prefill points from the server log of an amd-tracking matrix run (one wave per point):

```bash
python3 batch_log.py prefill server.stderr.log --benchmark-json RUN/tokenspeed/benchmark.json \
  --chunk-cost --tail --out-json prefill-log.json
```
