# tokenspeed/serving/ — measuring a running TokenSpeed server

Tools that drive a `ts serve` server over HTTP and read its log (`ts_control::batch_log` lines).
Server flags, server start/stop, fixed-batch decode, serving load, prefill and the real-token prompt
bank are owned by [lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking): the
recipes in `apps/inference_engine_benchmark/recipes/`, `skills/inference_engine/benchmark/scripts/manage_server.py`,
`apps/inference_engine_benchmark/scripts/run_nightly_tiered.py` (retained-KV harness),
`skills/inference_engine/benchmark/scripts/run_evalscope_matrix.py` (with `--output-tokens 1
--prefill-summary` for prefill) and `skills/inference_engine/retained-kv/scripts/prepare_token_corpus.py`
(`--format git-docs` builds the natural-prose text from a Git tree's documentation).

| Path | Measures |
| --- | --- |
| `batch_log.py` | The one parser of the server log (`Prefill`/`Mix`/`Decode batch.` lines and `Finish!` lines: `Finish! RequestStats(...)`, or, in builds that log only the request's mean accepted tokens per verify step (TokenSpeed `1be88db0a7b020d1cc45241eb02935c03d692335`), `Finish! Accept_num_tokens_avg: X`, read as a Finish event with stats `{"acc_len": X}` and no prompt/output token counts) and a log follower; every tool below imports it, and `acceptance_by_rid` is the one reader of per-request acceptance (the `acc_len` of either Finish form, by request id) for `e2e_decompose.py --accept-server-log` and `correctness/compare_outputs.py --accept-server-log`. `batch_log.py dp-spread LOG --window NAME=START[,END] ...` sums `#new-seq` of the Prefill lines per attention-DP rank in each time window (how evenly data-parallel placement spread a run's prefill work). `#new-seq` is the round's extend rows (TokenSpeed `ts-control/src/batch_log.rs`), so these are prefill rows, not requests: a prompt chunked over k rounds counts k times, a request prefilled only in Mix rounds (beside decode rows) not at all, and the lines carry no request id to count requests exactly; `--tokens` adds per window and rank (and `all`), over the Prefill and Mix lines, the prompt tokens prefilled (`#new-token`, which on a Mix line also holds its decode rows' tokens) and served from the prefix cache (`#cached-token`, counted on a request's first chunk), `cached_share` = cached / (cached + prefilled) (a lower bound of the prompt tokens' cache share), `mix_new_seq` and the Prefill, Mix and cache-hit line counts (whether later turns of a session reach the rank holding their prefix), and `--requests NAME=N` (the window's request count from the client, e.g. AIPerf's profiled requests) prefilled and cached tokens per request; `batch_log.py line-gaps THRESHOLD_S LOG...` lists per log and rank every gap above THRESHOLD_S s between consecutive batch lines with both lines' kinds and log timestamps (the times of prefill-chunk stalls); `batch_log.py prefill LOG --benchmark-json BJ [--chunk-cost] [--tail]` reads prefill points (one wave, one output token, e.g. amd-tracking's matrix with `--output-tokens 1 --prefill-summary`) from the log: per-rank chunks, chunk times and request split, validity (prefill tokens = B x L and no prefix-cache hit: RequestStats `cache_tokens == 0` when the log has RequestStats, else every Prefill/Mix line's `#cached-token == 0`; the source used is printed) and batching (steps, most requests present at once, per-step `new_seq/new_token`) |
| `sustained/` | A multi-turn agentic load replayed with EvalScope for a fixed duration, and the decode batch sizes the server actually ran (`build_workload.py`, `run_sustained.sh`, `analyze_sustained.py`, whose `--steady A:B` also gives client metrics over a steady window and `--instances` conversation counts); `prefix_reuse.py` measures how often later turns reuse their previous turn's cached prefix under data-parallel placement; both read the EvalScope database through `evalscope_db.py`, which also defines the steady window (each output names its anchor); `DATASET.md` characterises `lightseekorg/agentic-dataset` |
| `e2e_decompose.py` | Split one serving run's server log into per-rank prefill, decode and idle time, with residency, the round time at full batch and per rank `prefill_to_decode_gap_s` (count, median and largest gap between a Prefill/Mix line and the next Decode line, with both line timestamps, and the stalls above max(2 x (chunk + Decode-line interval), 1 s): a request stalled between its last chunk and its first decode); the busiest rank of a run is the one with the largest prefill + decode time in every table, model and fit. `--samples SAMPLES_JSONL` (amd-tracking `gpu_admission.py` admission samples, repeatable) adds to each stall the GPU activity of `../../profiling/gpu_activity.py` before, during and after it. `--benchmark-json` slices a whole log per phase of an amd-tracking EvalScope matrix run (a phase repeated across concurrencies, a matrix ladder, per point as `PHASE-cC`, slice `PHASE-cC.log`); `--markdown` prints one row per run. `--predict` models a closed-loop benchmark (R requests of L/O tokens at concurrency C) from prefill and decode measurements (`--prefill NAME=` an amd-tracking matrix `--prefill-summary` `benchmark.json`, `--tpot NAME=CFG:` a number or `CSV@POINT` of a `report_retained_kv.py --repetitions-only` table) and swaps measured terms between configurations. `--chunk-model` fits a chunk-time line t(x) = a + b x (`--chunk-fit NAME=JSON[,JSON]`, with its fixed share a/t(x) and its [min, max] over repetitions, or a stated `--chunk-line NAME=A_MS:B_US`) and what-ifs chunk size and placement (`--chunk-scenario NAME=LINE:CHUNK:GROUPS[:DECODE]` per `--concurrency-list` C). `--point-table JSON...` with `--decode-log-interval N` tabulates this tool's JSON per run: the busiest rank's chunks x median chunk ms, the full-batch decode round (Decode-line gap / N, upper median over ranks) and the largest `prefill_to_decode_gap_s`. `--accept-split REF=BENCHMARK_JSON --accept-split X=BENCHMARK_JSON ...` splits each run's mean latency gap to REF, per point paired by phase and concurrency, into a TTFT part and a decode part (median [min, max] of the per-repetition differences); with `--accept-decompose LABEL=JSON`, `--decode-log-interval N` and per-request acceptance (`--accept-requests LABEL=JSONL` from amd-tracking `evalscope_degeneracy.py --requests`, optionally `--accept-server-log LABEL=LOG`) the decode part splits further into decode-step, DSpark-acceptance and other parts, with the acceptance taken as the harmonic mean of per-request values from one source for both sides of a pair (see the module docstring for the formulas). `--window-from-aiperf PROFILE_EXPORT` (one per `--log`) decomposes only an AIPerf `profile_export.jsonl` profiling phase (first request start to last request end, over the records InferenceX's agentic aggregate counts: no `benchmark_phase` is profiling, errored records dropped) instead of the start/end rules, which assume fixed-length requests (agentic runs such as InferenceX AgentX), and reports the window's Finish lines (`window_finish_lines`: count, mean nonzero `acc_len`, requests with `acc_len` 0); on a single-rank log (Finish lines carry no DP rank) a gap holding Finish lines for every request running at its start ends decode at the last of them and counts the rest as idle between waves (`finish_split_gaps` per rank: how many gaps, how many start at a Prefill/Mix line such as a turn shorter than one Decode-line interval, and the prefill, decode and idle seconds they were given); `--step-table` (with `--decode-log-interval N`, rounds per Decode line) gives the decode round time from consecutive Decode lines of each rank (gap / N), binned by running batch and context (`avg_seq_len` bucket) over clean gaps only (no Prefill/Mix line of any rank between or just before them, same batch at both ends), with accepted tokens per round and ms per token per request, and per rank all clean gaps pooled (`clean_all`: n, median, p10, p90, min, max; the table's `all` row when there is more than one bin); it lists clean gaps above 1.5x their bin's median (pauses with no logged prefill), counts prefill-held gaps and their excess over the clean step, and Prefill/Mix rounds run while decode requests were resident. It generalizes the full-batch round time above to every batch size, for variable-batch (agentic) runs |
| `claim_run.py` | Runs several serving configurations on ONE GPU claim. `run` has amd-tracking `manage_server.py run --config FILE [--client ...] --emit-job` write one job per `--config NAME=FILE` (run dir `OUT/NAME`), records every input in `OUT/plan.json` and queues one `board/gpu-queue add --count N --idle-by --confirm [--hold-busy-free-cap --hold-gate-ranks]` job, `claim_run.py job OUT/plan.json`, which on the claimed GPUs, with core files off, per configuration in order: skips it when `OUT/STOP` exists or fewer than its `--min-seconds` remain before `--deadline-utc`, refuses a `--forbid-env` match in the job environment, waits until the GPUs have had no other user's KFD process for `--quiet-seconds` (amd-tracking `gpu_admission.py quiet`, giving up `--min-seconds` before the deadline, own = the job's group and `GPU_ADMISSION_OWN_PGIDS`, verdict in `OUT/quiet-NAME.json`), runs the emitted job in its own session (killed at the deadline), whose `manage_server.py run` refuses to start unless the TokenSpeed worktree is at `--tokenspeed-commit` without changes (emitted with `--require-tokenspeed-commit` and `--require-clean-tokenspeed`), and stops what it left: the session and, if `manage_server.py status` says it is up or fails, the server (`manage_server.py stop`); SIGTERM, SIGINT or SIGHUP (gpu-queue's process group stopped) stops both the same way, records the configuration as stopped and exits 128+signal. `OUT/STOP` is written on a foreign process during the wait of a `--stop-on-foreign NAME` configuration (guard needed; `quiet --stop-on-foreign` ends the wait at that sighting), a tree manage_server refused (run.json status `tokenspeed-source-refused`), a forbidden variable or an out-of-memory line in the server log; per configuration results in `OUT/claim-run.json`. `--start-method guarded` needs the hold options, puts `board/memgate` first on `PYTHONPATH` and names TokenSpeed's gate table `tokenspeed/memgate-gates.json` in `GPU_HOLD_GATE_TABLE`. After the queue job (or `claim_run.py post OUT/plan.json`), into `OUT/post/`: `--facts` (`manage_server.py facts --markdown --recompute`), `--decompose CLIENT` (`e2e_decompose.py --benchmark-json`, with `--prompt-tokens`, `--decode-log-interval`), `--summarize CLIENT` (`range_compare.py summarize --summary-key --summary-metric --summary-where`) and `--post-command CMD` (with `CLAIM_RUN_DIR_<NAME>` set, for comparisons across runs: `range_compare.py compare`, `decide.py`). Every campaign value is a required input; `--dry-run` prints every command, the in-claim steps included, and writes nothing |
| `correctness/` | Greedy-output consistency: `greedy_prompts.py` builds a seeded prompt set from a text corpus, `greedy_client.py` records outputs for it, `compare_outputs.py` compares runs token by token (`--pair` for several, `--cache-free` for prompts without prefix-cache hits, `--key prompt_sha256 --where concurrency=1` to pair amd-tracking `evalscope_degeneracy.py --requests` records of two serving runs by prompt, with each side's acceptance and loop period, `--rows` for every row, `--accept-test` for acceptance distributions, paired tests and looping per prompt with a Wilson interval, `--accept-server-log LABEL=LOG` for the server's per-request acceptance), `probe.py` asks the server for its own top-1 token where two outputs first diverge (`--mode decode-path`, `--mode teacher-forced`, `--summarize`); `eval_agreement.py` asks whether configurations agree on an EvalScope accuracy benchmark (per-repetition scores from a `manage_server.py` run, then a binomial agreement verdict per pair; `compare --counts-from-summary` from the summaries' counts alone, `--admissible-only` without repetitions whose window was not admissible) |
| `decide.py` | Whether configuration X beat a reference REF at each point: from per-repetition benchmark tables, the ratio of medians with a percentile bootstrap interval (`../../numerics/range_compare.py`; at least `--min-repetitions` 5 per side, else `incomplete`), `won` / `lost` / `no verdict`, and three flags read from the owners' outputs: the acceptance share of `e2e_decompose.py --accept-split`, disjoint looping intervals of `correctness/compare_outputs.py --accept-test`, and a canonical-table range verdict opposite to the decision; a flagged point takes a re-run's word (`--rerun-*`) |

Comparing configurations (ratios with a range-overlap verdict) is `../../numerics/range_compare.py`
over the summary tables these tools write (`decide.py` for a per-point verdict with flags); output degeneracy of any of their outputs is amd-tracking's
`skills/inference_engine/benchmark/scripts/evalscope_degeneracy.py --input LABEL=PATH`.
Tests (CPU, synthetic logs from `log_fixtures.py`): `test_batch_log.py`, `test_e2e_decompose.py`, `test_decide.py`, `test_claim_run.py` (a fake host: no GPU, queue or server), `sustained/test_sustained.py`,
`correctness/test_correctness.py`, `correctness/test_eval_agreement.py`.

Requirements: the model directory in `MODEL` (or `--tokenizer`), a client Python with `aiohttp`,
`numpy` and `transformers` (an EvalScope virtual environment has them), for
`sustained/` the `evalscope` executable in `EVALSCOPE`, and a checkout of
[lightseekorg/amd-tracking](https://github.com/lightseekorg/amd-tracking) in `AT`: servers are
started, guarded and stopped with its `manage_server.py`, which waits for the GPU set to be idle.

Prefill points from the server log of an amd-tracking matrix run (one wave per point):

```bash
python3 batch_log.py prefill server.stderr.log --benchmark-json RUN/tokenspeed/benchmark.json \
  --chunk-cost --tail --out-json prefill-log.json
```
