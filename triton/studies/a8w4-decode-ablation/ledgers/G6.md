# G6 — grouped single-buffer direct-load transport (drop the async pipeline at tiny M)

## The idea in one breath

At decode-sized M, throw away the general async multi-buffer software pipeline that streams X/W/scales from global memory and replace it with the simplest possible transport: each K-tile does plain wave32 global loads, drops the data into one LDS stage, and feeds the WMMA immediately — no prefetch, no double buffering, no tensor descriptors on the input path.

## Why anyone would want this

The baseline (H0) treats input movement like a prefill problem. It builds tensor descriptors for X, W, and the weight scales, allocates `NUM_BUFFERS` LDS stages, and runs a classic prefetch pipeline: while the WMMA chews on the tile for iteration N, the hardware is already async-copying tile N+1 into a different LDS buffer. That overlap is exactly what you want when K is long and each tile is big — the copy latency hides completely behind a fat pile of math.

Decode is the opposite regime. M is 1–4 rows. There is very little math per K-tile, so there is very little compute to hide the copy behind, and the machinery you paid for — extra LDS buffers, descriptor setup, prologue/epilogue predication, the whole modulo-`NUM_BUFFERS` bookkeeping — is overhead that never gets amortized. The bet in G6: at tiny M the pipeline is not buying you overlap, it is just cost. So strip it to a single stage and load directly.

## Picture: pipeline depth collapse

```
BEFORE (H0, multi-buffer TDM pipeline, NUM_BUFFERS>=2)

  descriptors: X_desc  W_desc  Wscale_desc   <- built once up front
  LDS:         [ buf0 ][ buf1 ]              <- NUM_BUFFERS stages

  iter 0:  async_copy tile0 -> buf0
  iter 1:  async_copy tile1 -> buf1 |  (nothing to compute yet: prologue)
  iter 2:  async_copy tile2 -> buf0 |  WMMA(buf1 = tile1)   <-- copy N+1
  iter 3:  async_copy tile3 -> buf1 |  WMMA(buf0 = tile2)       overlaps
   ...        (load-ahead)          |     (compute)             compute
           \___________________  overlap depth = NUM_BUFFERS-1 ________/


AFTER (G6, single-buffer direct load, NUM_BUFFERS==1)

  no input descriptors. one LDS stage, reused every iteration.

  k_tile 0:  gl.load X,W,scale  ->  write X,W to LDS  ->  WMMA   (serial)
  k_tile 1:  gl.load X,W,scale  ->  write X,W to LDS  ->  WMMA
  k_tile 2:  gl.load X,W,scale  ->  write X,W to LDS  ->  WMMA
             \_ load _/            \__ one stage __/       \_math_/
             pipeline depth = 1  (load, then use, then repeat)
```

The whole `load-ahead vs. compute` column disappears. There is no "tile N+1" in flight; the loop is load → stage → compute, strictly in order, on one buffer that the next iteration overwrites.

## Baseline vs. this idea, concretely

What gets removed: the input tensor descriptors (`create_descriptor`), the `MoEPipelinedProgram` prologue/steady-state/epilogue pipeline, the `async_load` / `async_gather` TDM copies, the `async_wait` counting keyed off `NUM_LOADS_IN_BATCH`, and every LDS buffer past the first. The `NUM_BUFFERS` knob is not tuned — it is pinned to 1 and anything else is rejected at compile time.

What replaces it: a single helper that, per K-tile, constructs explicit X / packed-W / weight-scale pointers with tail masks on M, N, and K; issues ordinary `gl.load`s into wave32-distributed registers; initializes exactly one X LDS tile and one W LDS tile from those register values; reloads them in the WMMA dot layouts; and issues the same grouped scaled-WMMA. The next K-tile reuses the same conceptual stage.

What is deliberately unchanged: this is a transport-only swap. Grouped ragged-M program ownership, the per-expert routing/base-pointer decode, FP32 accumulation, bias, FP8 output conversion, and the gather/scatter writeback (which still uses TDM — it is output, not input) are all inherited verbatim from H0. That is the point of the ablation: hold the math and the ownership fixed so any later H0-vs-G6 hardware delta is attributable to the input transport and not to a dozen confounded changes.

## The honest part

This cell was validated under FFM, which is a **correctness** model with **no timing**. So the plausible-sounding performance story above — "the pipeline is overkill at tiny M" — is a *hypothesis*, not a measured result. What is actually proven here is two things: (1) the direct-load transport is numerically identical to the baseline across the full 25-case matrix (zero abs / rel / RMS error on every case, including K/N-tail and preshuffled-scale adversaries), and (2) the TDM machinery is genuinely gone, not just bypassed (TTGIR confirmed below). Whether that simpler transport is actually *faster* at tiny M — the crossover point, occupancy, register pressure from the explicit loads, LDS-bank behavior — is exactly what FFM cannot tell you and is left for hardware. G6 makes no performance claim; it establishes that the idea is a correct, isolated, measurable swap.
