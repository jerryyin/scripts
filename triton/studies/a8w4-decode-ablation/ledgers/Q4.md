# Q4 — fused softmax top-k plus grouped route materialization

## The idea in one breath

Instead of one kernel writing the top-k expert IDs and weights out to global memory and a second kernel reading them back to build the routing metadata, do both in a single workgroup: the top-k selection stays in registers/LDS and flows straight into the histogram-and-schedule construction, so the tiny intermediate never leaves the chip. This composes the two owned parents — Q1's softmax top-k router (k18) and Q3's precomputed-top-k grouping (k20) — by removing only the global boundary between them.

## What problem this attacks

A MoE decode step routes a handful of tokens (here M up to 16, top_k a few) to experts. That routing is two logical phases. First a router turns per-expert logits into a top-k set of expert IDs plus a softmax gate weight per pick (that's Q1). Then a grouping phase turns those scattered picks into the bookkeeping the GEMM actually needs: a per-expert count histogram, prefix offsets, a block schedule, and stable gather/scatter permutations plus the final gates (that's Q3). Classically these are two separate kernel launches, and the handoff between them is two global tensors — the `[M, top_k]` IDs and the `[M, top_k]` weights.

At decode, that handoff is almost pure overhead. The intermediate is minuscule — at most 64 routes total — but you still pay a full kernel-launch boundary and a global write-then-read round trip to move it. The compute on either side is trivial; the fixed cost of crossing global memory and relaunching dwarfs the actual work. This is exactly the regime where fusion pays: the work is too small to amortize the plumbing.

## Before and after

```
BEFORE (Q1 -> Q3, two kernels, global handoff)

  logits[M,E] --> [ Q1 kernel ]
                     softmax + top-k
                        |
                        v  GLOBAL WRITE  (top-k IDs, top-k weights)
                  +--------------------+
                  |  global memory     |   <-- the eliminated boundary
                  |  ids[M,tk], w[M,tk]|
                  +--------------------+
                        |  GLOBAL READ + second launch
                        v
                  [ Q3 kernel ]
                     histogram / offsets / schedule
                     gather / scatter / gates
                        |
                        v
                  grouped metadata (7 fields)


AFTER (Q4, one kernel, one workgroup)

  logits[M,E] --> [ Q4 kernel ]
                     softmax + top-k          (Q1 math)
                        |
                        |  IDs & gates stay in registers / LDS
                        |  (no global write, no read, no relaunch)
                        v
                     histogram / offsets / schedule
                     gather / scatter / gates  (Q3 math)
                        |
                        v
                  grouped metadata (7 fields)
```

The single thing Q4 removes is the boxed global buffer and the launch that straddles it. Everything above and below is unchanged: same softmax, same tie-breaking, same normalization/scale, same grouping and schedule logic. The picked IDs and weights now live as in-program SSA values that get handed directly from the selection loop into the grouping code within the same workgroup.

## Why the intermediate can just stay on-chip

There is nothing about the top-k arrays that forces them into global memory — they were only there because a kernel boundary was there. Once both phases share one workgroup, the selected IDs and gates are already the right size to hold in registers, and where the phases genuinely need to cooperate across lanes (reductions, the histogram, the prefix scans, the stable-rank match), the compiler lowers those collectives to shared memory.

That is worth being precise about: this is *not* a "everything fits in registers, no memory traffic at all" claim. The fused kernel still uses LDS — the compiler emits real dynamic shared-memory allocations (128 bytes for the small cases, 256 bytes for the G=64 case) and `ds_*`/barrier instructions for the layout conversions, histogram, and scans. The key distinction is *what kind* of memory: that LDS is compiler-managed scratch for on-chip collectives inside one workgroup, not a reintroduced global route tensor. Global scratch stays at zero. The IR proof is that the fused kernel's signature has exactly one input load (the logits) and only the seven final output pointers — there is simply no top-k IDs/weights pointer anywhere, so there is no place for the intermediate to round-trip through global memory.

## What "correct" means here (and what it doesn't)

This cell was validated under FFM, the functional model, which checks correctness only and has no meaningful timing. So the claim Q4 actually earns is a numerical one: the fused kernel's seven output fields match, bit-for-bit on integers and within tight FP tolerance (in practice exactly) on gates, the output of literally running the real Q1 kernel followed by the real Q3 kernel on the same inputs. They even reconstructed the original top-k IDs and weights back out of Q4's grouped permutation and confirmed those matched Q1's intermediates exactly. Ties resolve to the smaller expert ID just like Q1; normalization and scale behave just like Q1.

What Q4 does *not* claim is a speedup. FFM can't measure one, and it's genuinely an open question whether removing two global tensors and one launch pays for the fused program's larger live register state and its on-chip collective cost. The honest headline is narrow and strong: the global top-k boundary is provably gone from the IR, and the fused result is numerically identical to the two-kernel composition. Whether that translates to wall-clock is left to a timing model, not this cell. Q5 is the biased analogue of this cell — it still owns correction-bias/group-limited selection, and Q6 still owns any M=1 shortcut.

- Before Q4, Q1 program 0 owns `M x E` logits and globally stores `M x top_k` IDs/weights; Q3 program 0 reloads those two tensors, groups them, stores seven final fields. The explicit boundary is two global intermediate tensors and two launches.
- After Q4, one grid program owns logits, Q1 softmax/selection state, flat selected IDs/weights, and Q3 grouping state. Selected routes remain in device-local SSA values from selection through histogram and stable-rank placement; only the seven final fields are global outputs.
