### Frozen input, weight, routing, and output ABI

- Child ABI: `invoke_output_owned_a8w4_topk(intermediate, intermediate_scale, packed_down_weight, down_weight_scale, route_ids, routing_weights, down_bias, *, expert_start, block_n, block_k, num_warps, capture_components=False)`.
- Let `M, TOP_K = route_ids.shape`, `R = M*TOP_K`, down-projection input width be `K`, and output width be `N`.
- `intermediate` is contiguous `torch.float8_e4m3fn` `[R,K]` in token-major/top-k-slot order. It is a prebuilt W1 boundary; R5 neither computes gate/up nor quantizes/dequantizes a W1 result.
- `intermediate_scale` is contiguous FP32 `[R]`, one explicit dequantization multiplier per route row. Each K fragment is interpreted as `intermediate[route].float() * intermediate_scale[route]`, exactly adapting R1's A8-plus-scale vector multiply to per-route W2 inputs.
- `packed_down_weight` is contiguous uint8 packed E2M1 `[E,K/2,N]`; raw compact UE8M0 `down_weight_scale` is contiguous uint8 `[E,K/32,N]`. R5 retains R1's gfx1250 `scaled_upcast(..., gl.bfloat16, axis=1)` and FP32 elementwise reduction; it does not add scaled MFMA/WMMA.
- `route_ids` is contiguous int32 `[M,TOP_K]` with global IDs localized by `expert_start`. All routes must be local, retaining R1's fail-fast contract rather than importing TokenSpeed's EP skip behavior.
- `routing_weights` is contiguous FP32 `[M,TOP_K]`. Values must be finite but need not sum to one; a routed scaling factor is therefore representable. Each weight multiplies its route projection in FP32.
- Optional `down_bias` is contiguous FP32 `[E,N]`. It is added to each selected-expert route projection before routing-weight multiplication, preserving the R1 per-route projection contract.
- Each route projection, routing-weight product, prefix partial accumulation, and final output remains FP32. The semantic output is contiguous FP32 `[M,N]`, with slots accumulated in increasing top-k order and one final token-row store.
- `capture_components=True` is constexpr-gated correctness instrumentation that exposes FP32 `[R,N]` route projections, weighted projections, and after-slot prefix accumulations. Production `capture_components=False` allocates no per-route output/combine buffers and must lower to one semantic final store.
- Numerical acceptance remains R1's pinned A8W4 contract: normalized `maxtol=3e-2` and effective `rmstol=4e-3`, applied separately to every captured route projection, weighted product, partial accumulation, and final output. Tolerance will not be loosened after failure.

### Ownership, primitive, buffers, and tuning axes

- Before: R1 maps each program to `(route, N tile)`, derives its token/slot, computes one selected-expert projection, and writes one FP32 `[R,N]` route row. A later consumer would need routing-weight multiplication and top-k combine.
- After: R5 maps each program to `(token, N tile)`, loops `TOP_K` inside the owner, recomputes the inherited selected-expert wave GEMV per slot, weights and accumulates in registers, and writes one FP32 `[M,N]` token row.
- Expert grouping, padded M, gather/scatter staging, TDM/LDS matrix tiles, cross-wave synchronization, atomics, MFMA, and WMMA remain absent.
- Production global buffers are the prebuilt per-route intermediate/scale, packed selected-expert down weights/scales, route IDs/weights, optional bias, and final token output. No per-route W2 output, partial-combine buffer, or separate reduction kernel exists.
- Exposed `BLOCK_N` remains `{4,8}`.
- `NUM_WARPS` remains intrinsically equal to `BLOCK_N`, one gfx1250 wave per output column; legal values `{4,8}` are both exercised.
- Exposed `BLOCK_K` remains `{256,512}` logical intermediate elements, retaining R1's power-of-two, 32-element scale-group, exact-K-divisor, and four-packed-bytes-per-lane requirements.
- `TOP_K∈{1,4}` and `M∈{1,4}` are workload semantics, not tuning axes. `SCALE_BLOCK=32` and component capture are numerical/test semantics.

### Failure isolation during validation

- The first smoke reached FFM and all four numerical boundaries passed, but the production-IR negative-space gate found that a single constexpr-gated entry still retained three unused capture pointer formals. R5 split production and capture entry signatures over one shared device implementation. The resulting production TTGIR has neither the formals nor the stores.
- Early full runs exposed an audit-model error, not a device numerical error: `TOP_K` is statically unrolled in TTGIR, while the K loop has one TTGIR upcast op per slot and backend expansion emits one native pk8 instruction per 256 logical K elements. The gate was corrected to the observed compiler structure (`TOP_K` TTGIR ops and `TOP_K*K/256` native instructions); no numerical tolerance, ABI, or device computation changed.

## Alternatives Considered

- Importing TokenSpeed's BF16 intermediate and per-route BF16 projection rounding was rejected because that would combine R3's numerical boundary with R5's structural ownership.
- Consuming R4's static-FP8 output scale convention inside a W1 producer was rejected because R5 is W2-only. Its input simply declares prebuilt E4M3 rows and explicit row scales.
- Writing per-route W2 rows followed by a separate combine was rejected because that preserves R1 ownership and is exactly the boundary R5 removes.
- FP32 atomics into token output were rejected because they preserve grouped/route owners; G7 separately owns the atomic-combine alternative.
- Direct scaled MFMA and K lookahead were rejected because R7 and R8 own those changes. R5 retains R1's wave reduction.
