### Changed ABI and numerical reference

- Parent ABI/reference: H0 consumes expert-grouped ragged metadata, block schedules, optional gather/scatter indices, A8 activation plus packed E2M1/UE8M0 weights, and bias. A program owns an `(expert M block, N tile)` and produces an output rounded to the activation FP8 dtype. Its reference is grouped `matmul_torch`.
- R1 ABI: `invoke_route_direct_a8w4_wave_gemv(x, x_scale, packed_weight, weight_scale, route_ids, bias, *, expert_start, block_n, block_k, num_warps)`. `x` is contiguous E4M3 `[M,K]`; `x_scale` is explicit contiguous FP32 `[M]`; packed E2M1 `weight` is contiguous `[E,K/2,N]`; raw UE8M0 `weight_scale` is contiguous `[E,K/32,N]`; global `route_ids` is contiguous int32 `[M,top_k]`; optional FP32 `bias` is `[E,N]`; and `expert_start` localizes global route IDs. The output is one FP32 row per direct route, shape `[M*top_k,N]`, in token-major/top-k-slot order. No route weights or top-k combine are part of R1; R5 owns that later boundary.
- R1 reference: dequantize packed E2M1 plus UE8M0 to exact BF16 weight values, convert stored E4M3 activation values to FP32, explicitly multiply each token row by its FP32 activation scale, form each selected-expert dot product in FP32, add selected-expert FP32 bias, and retain the FP32 route row. This is intentionally not H0's grouped/FP8-output reference.
- Numerical acceptance remains the pinned A8W4 source contract: `maxtol=3e-2` and the existing `assert_close` default effective RMS tolerance `4e-3`. No tolerance will be changed in response to a failure.

### Configuration and cases

- Exposed tuning axis `BLOCK_N`: `{4,8}` in the required full matrix.
- `NUM_WARPS` is intrinsically equal to `BLOCK_N`, because this implementation assigns exactly one gfx1250 wave to each output column in the tile. Both legal values `{4,8}` are exercised; mismatched values are rejected before launch.
- Exposed tuning axis `BLOCK_K`: logical activation elements `{256,512}` in the required full matrix. It must be a power of two, divisible by the native 32-element MX scale group, divide `K` exactly, and distribute at least four packed bytes to every gfx1250 lane. Both legal values are exercised. `BLOCK_K=128` was independently compiled before the restriction was frozen and hit `ScaledUpcastToLLVM.cpp:94`'s `inputVals.size() % 4 == 0` assertion because it gives only two packed bytes per lane; the public wrapper now rejects it explicitly.

## Parent → child ownership change

- Before: H0 maps one program ID through expert-grouped ragged block schedules to `(expert block, padded M tile, N tile)`, stages X/W/scales through TDM and LDS, uses scaled WMMA for the K reduction, and stores/scatters a routed row after FP8 output conversion.
- After: R1 maps one program directly to `(route, N tile)`, derives `token = route // top_k`, localizes the selected route ID, streams only that expert's packed weight bytes and UE8M0 scales, applies the explicit A8 activation scale around an elementwise FP32 multiply, reduces K with `gl.sum` within the owning wave, adds bias in FP32, and writes the route's unique FP32 row.
- Expert grouping, group histograms, ragged block schedules, padded M tiles, gather/scatter buffers, TDM, LDS matrix tiles, MFMA, and WMMA are absent after the fork.
- Global traffic after the fork is direct activation, selected-expert weight/scale, route-ID, optional bias, and one route-row output. The accumulator is register-resident; no global scratch or shared-memory matrix handoff is allowed.

## Alternatives Considered

- Reusing H0's grouped `_matmul_decode` ABI was rejected because it would still consume expert grouping, padded M metadata, and the grouped reference, directly violating R1's ownership change.
- Porting TokenSpeed's A16W4 activation input unchanged was rejected because R1 must preserve the A8W4 destination. R1 instead exposes an E4M3 activation and applies its explicit FP32 scale around the vector multiply.
- Scalar nibble/exponent decoding was rejected because gfx1250's pinned `scaled_upcast` API directly supports packed E2M1 plus compact raw UE8M0 scales and is the closer precision-matched mechanism.
- Retaining `BLOCK_K=128` through scalar decoding or compiler modification was rejected: either would introduce a second idea and erase the native gfx1250 scaled-upcast boundary this cell is meant to test.
- Gate/up reuse, BF16/static-FP8 intermediate emission, top-k weighting, and matrix primitives are not folded into R1 because R2–R8 own those independent ideas.
