# G5 — AITER-style preshuffled packed weights

## The idea in one breath

Store the 4-bit packed weights in global memory in AITER's gfx1250-specific permuted byte order — the order that makes a weight tile land in memory exactly the way the WMMA consumer wants to stream it — then apply the inverse permutation cheaply inside LDS so the math still sees the ordinary logical tile. The global load gets contiguity for free; the reordering cost moves offline (host preshuffle) plus a near-free on-chip reshape.

## Why anyone would do this

The expensive resource in tiny-M decode is *global memory traffic*, not compute. There is almost no M to amortize a weight load over, so the weights dominate. If the bytes you fetch for one weight tile are scattered in a layout that the WMMA fragment doesn't consume in that order, each K-step's global read is strided and pays extra transactions. The trick: pick the *storage* layout so that the contiguous run of bytes on the K axis (the dimension you march down every iteration) is exactly the run the hardware ingests together. You do the "make it awkward" work once, on the host, and the "make it convenient again" work in LDS where a permute is just an addressing pattern, not a memory round-trip.

## The picture

Work with one expert's packed matrix in `(N, Kp)` coordinates, where `Kp = K/2` because two E2M1 nibbles share a byte. Take a tiny slice: `N = 32` rows, `Kp = 64` packed-K bytes. AITER tiles this into 16-wide N groups and 32-wide Kp groups, then interleaves.

**1. Natural / logical layout** — what the math wants. Byte at logical coordinate `(n, kp)`:

```
        kp=0   kp=1   ...  kp=31  kp=32  ...  kp=63
n=0     a00    a01         a0,31  a0,32       a0,63
n=1     ...
...
n=15
n=16                                          (second N group)
...
n=31
```

**2. Preshuffled global layout** — what H0/G5 actually stores. The host takes `(N/16, 16, Kp/32, 2, 16)` and permutes it to `(N/16, Kp/32, 2, 16, 16)`, then flattens to physical `(N/16, Kp*16)`. Concretely, the byte living at logical `(n, kp)` moves to physical row/col:

```
physical_k = (((kp//32)*2 + (kp%32)//16) * 16 + n%16) * 16 + kp%16
physical_n =  n//16
```

Equivalently, `physical[(((kp//32)*2 + (kp%32)//16)*16 + n%16)*16 + kp%16, n//16] = ordinary[kp,n]`. A few sample bytes (from the kernel's own round-trip proof):

| logical (n, kp) | physical (physical_k, physical_n) |
|---|---|
| (0, 0)   | (0, 0)      |
| (15, 31) | (511, 0)    |
| (16, 32) | (512, 1)    |
| (31, 63) | (1023, 1)   |
| (7, 48)  | (880, 0)    |

Read the formula from the inside out: the fast-moving physical index is `kp%16` (16 contiguous packed-K bytes), then `n%16` (the 16 rows of an N group), then the 2 halves of the 32-wide K group, then the K-group index. The 16 packed-K bytes for a fixed `(n%16)` are now physically adjacent, and the whole 16×16 `(n%16, kp%16)` sub-tile is one dense 256-byte run — that is the shape a WMMA weight fragment eats. The slow axis is `physical_n = n//16`, so an N tile of `BLOCK_N` rows collapses to `BLOCK_N/16` physical rows, each `PACKED_K * 16` bytes wide. The global load is now a big contiguous strip along the K march instead of a gather.

**3. Local inverse in LDS** — restore the logical tile before the dot. After TDM lands the physical tile `(BLOCK_N/16, (BLOCK_K/2)*16)` in shared memory, the kernel undoes the interleave with a pure index shuffle (`unshuffle_weight_gfx1250`, k05 lines 276-279):

```
reshape (BLOCK_N/16, (BLOCK_K/2)/16, 16, 16)   # split both wide axes back into 16s
permute (0, 2, 1, 3)                            # swap the two inner 16-blocks
reshape (BLOCK_N, BLOCK_K/2)                     # → the ordinary logical tile
```

That permute is the exact transpose of the host's `permute(0,1,3,4,2,5)` restricted to a tile. No extra global traffic, no arithmetic — the values feeding scaled-WMMA are byte-for-byte the H0 values.

## Baseline vs. this idea

| | H0 (k00) | G5 (k05) |
|---|---|---|
| Global weight layout | logical packed `(K/2, N)` | AITER physical `(Kp_padded*16, N/16)` |
| Per-K-step global read | `(BLOCK_K/2, BLOCK_N)` logical tile | `(BLOCK_N/16, (BLOCK_K/2)*16)` contiguous strip |
| K-step offset unit | `BLOCK_K/2` bytes | `(BLOCK_K/2)*16` bytes |
| N-tile offset | `pid_n * BLOCK_N` | `pid_n * (BLOCK_N/16)` |
| Restore-to-logical | none | one LDS reshape/permute/reshape |
| Everything else | — | identical: routing, activation, scales, WMMA, accumulate, bias, writeback |

Only the weight *transport* changes. G5 keeps H0's whole compute spine — including H0's independent scale-preshuffle axis (weight preshuffle factor is 16; H0's scale preshuffle factor is 128, a separate knob). The two never touch each other, which is why C4 can run G5 weights *and* preshuffled scales at once.

## The K = 416 zero-padding wrinkle

AITER's permutation groups Kp into blocks of 32, so `Kp` must be a multiple of 32. H0 case C3 has `K = 416` → `Kp = 208`, which is not (208 = 6·32 + 16). The fix is mechanical and lives entirely on the host: pad the packed-K extent from 208 to 224 (the next multiple of 32) with **physical zero bytes** before permuting, while the reference and the kernel's K loop keep the true logical `K = 416`. The 16 pad bytes are zeros, so they contribute nothing to the dot; the real tail survives transport untouched. This keeps the exact awkward shape as a test rather than rounding K up to a friendly value.

## Honest scope

FFM = **correctness only, no timing**. All 25 retained cases (20 defaults + C1–C5) matched H0 with max abs error `0.0` — the preshuffle round-trips exactly, and saved TTGIR confirms the physical descriptor, physical K stepping, and the LDS inverse are all present (not optimized away). Whether this *actually* cuts global-memory transactions on real MI450 silicon, or merely relocates the address arithmetic into host prep and LDS metadata, is a hardware-timing question and is explicitly out of scope for this cell.
