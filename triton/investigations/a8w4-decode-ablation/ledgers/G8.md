The changed ABI is frozen as follows:

- The output value tensor is E4M3 and preserves H0's grouped row order.
- Its companion scale tensor is contiguous row-major `uint8 [M, yN / 32]`, where `yN = N / ACTIVATION_REDUCTION_N`.
- `N`, `BLOCK_N`, and the post-activation output width must give complete 32-column groups. The wrapper rejects incompatible values rather than silently sharing one group across programs or padding a semantic partial group.
- Like the AITER donor's GEMM1 path, gather or already-grouped input is legal, but output scatter is rejected. Each program remains the sole owner of its grouped output rows and N tile.
- Invalid ragged rows and tail columns are set to zero before the per-group maximum. Only valid complete groups are stored.
- For each FP32 group, the kernel computes `amax`, bitcasts it to `int32`, adds `0x200000`, masks with `0xFF800000`, bitcasts back to FP32, evaluates `floor(log2(...)) - 8`, clamps to `[-127, 127]`, and stores the biased exponent as a UE8M0 byte. It multiplies the group by `exp2(-scale_unbiased)` and casts to E4M3.
- An all-zero group therefore emits E4M3 zero bytes and UE8M0 byte `0`; ordinary finite groups emit scale bytes in `[0, 254]`.

Program-ID ownership, expert grouping, scaled-WMMA primitive, input/weight LDS and global-buffer traffic, K-loop, FP32 accumulation, bias, and activation position are unchanged from H0. The only new traffic is one global UE8M0 byte per owned output group; H0's output TDM store now carries E4M3 values instead of its inherited output dtype.

## Parent → child ownership change

H0 and G8 assign the same `(expert-grouped ragged-M tile, N tile)` to every program. `compute_pids`, `compute_offsets`, expert and slice metadata, gather behavior, X/W/scale descriptors, multibuffer TDM pipeline, scaled-WMMA formats/layout, FP32 accumulator, expert bias, activation position, and every K-loop decision are unchanged. An AST digest check confirms all nine frozen common helpers and classes are identical to H0.

H0 converts the full FP32 post-bias/post-activation tile directly to the caller-selected output dtype and sends it through output LDS and one TDM store or scatter. G8 forbids scatter, because its AITER-provenance ABI is GEMM1-style. It masks invalid ragged rows and N-tail cells to zero, reshapes each program-owned output tile to `[BLOCK_M, OUT_BLOCK_N/32, 32]`, derives one dynamic scale per group, emits E4M3 values through the inherited LDS/TDM path, and directly stores the companion scale byte to row-major `[M, yN/32]`.

The N-tail case proves the ownership boundary: `N=320, BLOCK_N=128` launches three N programs. The last program owns two valid complete groups and two padded groups. Padding participates as zero during reduction, but only the two semantic groups are stored. No group is split across programs.

## Alternatives Considered

- Static scalar FP8 scaling is the separate R4 boundary and does not test donor-exact dynamic per-group scaling.
- BF16 intermediate emission is the separate R3 boundary.
- Moving quantization into a standalone launch would retain neither the AITER fused epilogue nor this cell's single W1 boundary change.
- Output-owned or direct-route compute would change ownership and belongs to other cells.

## Inferred

Because each program owns complete 32-column output groups and the generated child performs the scale reduction/store in the same kernel as scaled WMMA, a downstream W2 consumer can read a strict MXFP8 intermediate without a standalone dynamic-quant launch. That pipeline consequence is inferred because G8 does not implement or run W2.

The no-scatter contract is structural, not a missing optimization: scattering rows after independently deriving scales would require an aligned scale scatter with identical row ownership. That is a separate ownership/ABI idea and is intentionally excluded here.
