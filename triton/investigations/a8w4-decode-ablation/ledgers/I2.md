### Frozen integration ABI and scale adapter

- Let `R=M*TOP_K`. The integrated caller supplies one contiguous FP32 repeated-static-scale buffer `[R]`: every element must have exactly the same four raw bytes, be finite, and be strictly positive.
- The public path passes the first contiguous `[1]` view to accepted R4 and passes the complete `[R]` buffer to accepted R5. Thus R4 consumes its scalar ABI and R5 consumes its per-route ABI without device-side replication, a device-to-device scale copy, arithmetic transform, inverse, rerounding, or scale-producing kernel.
- Exact-bit contract validation deliberately reads the scale to the host before dispatch. That synchronous validation copy does not mutate or recreate the CUDA buffer and is not a Gluon launch, but it means this correctness wrapper should not be mistaken for a timing-ready production wrapper.
- The repeated physical representation is one logical scalar. A scalar-only `[1]` buffer when `R>1`, a per-route value with different bits, a per-32 tensor, zero, or non-finite value rejects before either launch.
- R4 output width must equal R5 input K, and W1/W2 local expert counts must match. These integration incompatibilities reject before launch.
- W1 input remains E4M3 plus FP32 token scale; W1 and W2 weights remain packed E2M1 plus compact UE8M0; route IDs are global/localized by `expert_start`; routing weights are FP32; final output is FP32 `[M,N]`.
- R4 gate, up, SiLU, and product remain FP32 before the exact static E4M3 boundary. R5 interprets every route as `fp8.float() * repeated_static_scale[route]`, preserves its FP32 route/bias/weight/prefix order, and stores once per token/output element.
- No BF16 intermediate boundary, dynamic/per-32 output scale, output-scale derivation, grouping, LDS/TDM transport, matrix instruction, atomics, lookahead, or extra combine appears.
