### Failure isolation and refutation history

1. The first runtime-enabled smoke reached input construction and refuted the harness assumption that plain E4M3/E5M2 activations take an MX scale dimension. The source `DType.has_mx_scale` check is false, so the harness now passes `mxfp_dim=None` and no MX activation-scale layout.
2. Planned C1 then reached child compilation and was rejected with:

   ```text
   'amdg.async_tdm_gather' op TDM gather padding interval must divide the innermost block dimension (got padInterval=256, innermost dimension=128)
   ```

   The frozen `MoEConfig` selects `PAD_INTERVAL_X=256` when packed activation K is at most 256. For plain FP8 and `BLOCK_K=128`, the gather descriptor's innermost block is 128, which cannot satisfy the verifier's divisibility rule. Planned C3 hit the same independently reproduced constraint.
3. Per the plan's replacement rule, only C1/C3 movement changed from gather to scatter. Their shapes, activation types, blocks, warps, buffers, layouts, and missing-axis values remained unchanged. Default gather cases at `BLOCK_K=256` passed, so the evidence isolates the boundary to the planned gather+`BLOCK_K=128` combination rather than gather generally.
4. The source tolerance audit refuted the initial `0.4/0.04` assumption: that branch is for MX-scaled output. These plain-FP8 A8W4 cases select `0.03/None`, with effective RMS `0.004`.
5. An early auxiliary metric compared the pre-rounded reference and showed nonzero error while source `assert_close` passed. Mirroring `assert_close`'s one-byte reference cast made the reported metric measure the actual acceptance boundary; every retained case then reported zero error.
